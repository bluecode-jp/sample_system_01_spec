# sample_system_01_spec

商品在庫管理システム **toy_ims**（子供向け玩具の在庫管理）の仕様書と、開発ノートを管理するリポジトリです。
実装コードは含みません。AI（Claude Code など）に仕様書を渡してシステムを開発させることを想定しています。

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| [`spec_01.md`](spec_01.md) | システムの仕様書（機能・非機能・データ・利用技術・開発情報・デザイン） |
| [`spec_01_dev_note.md`](spec_01_dev_note.md) | 同種のシステムを開発したときのハマりどころと対処をまとめた開発ノート |

## システム概要（仕様書の要約）

- **クライアント**：スマホ向け Web アプリ（React SPA）
  - バーコード（Code128）スキャン・手入力・商品名の部分一致検索
  - 在庫の加算・減算、商品詳細の表示
- **サーバ**
  - API：Cloud Functions for Firebase
  - 管理画面（React SPA）：商品・在庫管理、CSV 入出力、バーコード印字、QR 表示・印字、ユーザー管理
- **基盤**：Firebase（東京リージョン）
  - Hosting / Cloud Functions / Firestore（Enterprise）/ Storage / Authentication
  - 在庫数は Firestore の `onSnapshot` でリアルタイムに各画面へ反映
- **言語**：TypeScript

詳細は [`spec_01.md`](spec_01.md) を参照してください。

## 使い方

1. 実装用の新しいリポジトリ（作業ディレクトリ）を用意します。
2. AI に `spec_01.md` と `spec_01_dev_note.md` を読ませ、開発を依頼します。
   - 開発ノートは「前回の開発で詰まった点」をまとめたものです。最初に読ませることで、同じ問題を避けられます。
   - 仕様書の「留意事項」のとおり、AI は実装前に方針・プランを提示し、重要な不明点はユーザーに確認します。
3. 開発はローカルの Firebase エミュレータで動作確認し、その後に本番環境へデプロイします（ステージング環境は用意しません）。

## 更新方針

- 仕様を変更したら `spec_01.md` を更新します。
- 開発中に新たに分かった注意点は `spec_01_dev_note.md` に「症状 → 原因 → 対処」の形式で追記します。
