# sample_system_01_spec

AI（Claude Code など）にシステムを開発・デプロイさせるときに使う、仕様書と開発・デプロイのノートを管理するリポジトリです。
実装コードは含みません。

- **開発ノート・デプロイノート**：特定のプロジェクトに依存しない、汎用の注意点集です。同じ技術構成の案件なら、そのまま使えます。
- **仕様書**：ノートと組み合わせて使う仕様書の具体例です（商品在庫管理システム）。

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| [`spec_01.md`](spec_01.md) | 仕様書の例（機能・非機能・データ・利用技術・開発情報・デザイン） |
| [`spec_01_dev_note.md`](spec_01_dev_note.md) | 開発ノート：Firebase + React（TypeScript）でスマホ用バーコード Web アプリを開発するときの注意点 |
| [`spec_01_dep_note.md`](spec_01_dep_note.md) | デプロイノート：Firebase の本番環境を何もない状態から構築し、デプロイするときの注意点 |

## ノートが想定する技術構成

- **フロントエンド**：React（Vite）の SPA（スマホ用クライアントと管理画面の2つ）
- **バックエンド**：Cloud Functions for Firebase（第2世代、REST API）
- **Firebase**：Hosting / Firestore（Enterprise）/ Storage / Authentication（App Check は当面使わない）
- **言語**：TypeScript

ノート中の `<project-id>` や `<region>` などのプレースホルダーは、案件ごとに読み替えてください。

## 使い方

1. 実装用の新しいリポジトリ（作業ディレクトリ）を用意します。
2. 案件の仕様書を用意します。`spec_01.md` を下書きの参考にできます。
3. AI に仕様書と開発ノートを読ませ、開発を依頼します。
   - ノートは「前回の開発で詰まった点」をまとめたものです。最初に読ませることで、同じ問題を避けられます。
4. 本番環境へデプロイするときは、デプロイノートを読ませます。

## 更新方針

- 開発・デプロイで新たに分かった注意点は、各ノートに「症状 → 原因 → 対処」の形式で追記します。
- ノートには、特定のプロジェクトに依存する値（システム名・プロジェクトID・固有の画面の文言など）を書かず、プレースホルダーや「例」として書きます。
